**Design-compliance loop (every UI lane, Tiles That Talk run)** This runs in lane step d, after the gates are green and before review and the PR. The `impeccable` critique still runs too; this loop checks the build against the boards and DESIGN.md, and the critique checks its quality.
1. **Before set.** Before the first code change, serve the lane worktree at its base on the lane server and shoot every tab the ticket touches: `npm run shots -- http://localhost:<port> <scratch>/before "fixture=dry&age=3#<tab>" "fixture=raining&age=3#<tab>"`. Stop the server.
2. **Boards.** Fetch the boards the ticket names, or the boards for its tabs from the table above, with `git show` into `<scratch>/boards/`.
3. **After set.** On the finished branch, shoot the same queries into `<scratch>/after`. Add the clicked states the ticket changes (open finding row, open event row, 30 / 90, Total / Rate) from your own script.
4. **Compare.** Open each after shot beside its board, 1440 against 1440 (1280 before 1440 lands in `shots.mjs`) and 390 against 390, and check layout: tile order and grouping, columns, fixed top, finding rows, header, bottom tab bar, each part the board shows. Then check each shot against DESIGN.md, not the board: colour tokens for the theme (base keys light, `-dark` keys dark), Lexend in every word, the type steps for phone and from 760 px, no text under 12 px, chart grammar, one orange `now`. Also check at 390: no sideways scroll (`scrollWidth <= clientWidth`) on every tab, both fixtures, both themes.
5. **Fix the obvious, note the rest.** A difference is obvious, and the lane fixes it, when DESIGN.md or the spec settles which side is right. Examples: a part the board shows and the spec asks for is missing; tiles overlap or text is clipped or wraps out of its tile; a colour is not the token DESIGN.md names; a font, weight or size is off the type scale; text or a meaningful graphic fails its Contrast table minimum; sideways scroll at 390. A difference that neither DESIGN.md nor the spec settles is noted, not fixed: spacing that only the board shows, a chart proportion, wording the board uses and the spec does not. The lane never redesigns, never copies a board's number, size or inline colour, and never fixes outside its fence and ticket; a defect outside them is a held finding for the hand-back. After fixing, re-run the gates and reshoot.
6. **Into the PR body.** Push the before and after sets to the screenshot branch and add a section headed `Design compliance` to the PR body: a before / after table of links for each tab and width in dark and light, then a note in three lists. **Matches:** what lines up with the board and DESIGN.md. **Differs on purpose:** each difference and the line of the spec or DESIGN.md that decides it (a superseded board, a known board gap, a board number). **Left for review:** each unsettled difference and each held finding, one line each.
